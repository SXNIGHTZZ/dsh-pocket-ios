# 测试用例库

> 这里放**可复用的测试用例**，不是一次性的验证记录。
>
> 加用例的判据：**下次改到同一块代码时，你会想再跑一次它**。
> 跑完就丢的临时验证，写在 spec 或提交信息里，不要进这个文件。

## 一、性能压测场景（脚本化，可直接跑）

这些场景用环境变量切换，模拟器上就能跑，不需要真机、不需要连电脑。

```bash
./scripts/stress-run.sh <场景>
```

| 场景 | 验证点 | 当前基线 | 什么改动必须跑 |
| --- | --- | --- | --- |
| `messages:400` | 消息量大时的内存与滚动 | 400 MB | 列表容器、行高、内容裁剪 |
| `images:120` | 图片解码与缩略图缓存 | 307 MB | 图片加载/缓存/解码 |
| `steps:80` | 过程步骤渲染与展开 | 319 MB | 步骤折叠、过程行 |
| `sessions:800` | 列表规模与分组计算 | 277 MB | 会话列表、分组、排序 |
| `markdown:extreme` | 大表格 + 长代码块 | 466 MB | Markdown 渲染、表格样式 |
| `markdown:code:950` | 长代码块（历史崩溃点） | 381 MB | 代码块、语法高亮 |
| `markdown:table:200` | 大表格布局 | 483 MB | 表格样式、列宽 |
| `markdown:text:950` | 大量独立段落 | 593 MB | 段落渲染 |
| `markdown:singleline:950` | 单段落超长文本 | 381 MB | 长文本布局 |

**场景可叠加**：`./scripts/stress-run.sh "messages:400,images:120"`

**数据来源**：`DSHKit/StressScenario.swift`（解析 + 边界 clamp），
生成器在 `DSHPocket/Session/ConnectionModel+Demo.swift` 的 `stressMessages(scenarios:)`。

### 新增性能场景的步骤

1. 在 `StressScenario` 加 case + 解析（`markdown:xxx:N` 这种三段式）
2. 在 `stressMessages(scenarios:)` 加数据生成
3. 写单测（解析 + clamp）
4. `./scripts/stress-run.sh 新场景` 跑一遍，把数字填进 `performance-baseline.md`
5. 上表加一行

## 二、交互压测场景

| 场景 | 开关 | 验证点 | 已验证结果 |
| --- | --- | --- | --- |
| 连发消息 | `DSH_SEND_BURST=5` | 顺序、是否丢失、草稿残留 | 5 条全送达，间隔 1s，顺序正确 |
| 展开所有过程 | `DSH_EXPAND_STEPS=1` | 展开时的滚动与重绘 | 待测 |
| 自动滚到顶 | `DSH_SCROLL_TO_TOP=1` | 分页加载与位置保持 | 待测 |

**连发用例的写法要注意**：hook 里必须**模拟真实 UI**（等 `isSending` 结束再点），
否则测的是「程序化硬闯锁」——用户根本触发不了那个路径，会得出错误结论。

## 三、功能回归用例（手测清单）

每次改到对应模块，按这里的步骤走一遍。

### 消息渲染

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 进入一个含表格的会话 | 表格 1pt 线框、内容不挤成一行 |
| 2 | 找一条含代码块的消息 | 等宽字体、灰底、**无配色**（语法高亮已关） |
| 3 | 长按消息 | 菜单弹出（复制/引用等） |
| 4 | 引用一条消息再发送 | 发送内容带 `>` 引用块 |

### 消息列表

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 打开 400 条消息的会话（`messages:400`） | 只显示最近 24 条 |
| 2 | 往上滑到顶 | 不能看到更早的历史（硬裁剪设计） |
| 3 | 滚动到底 | 流畅，无跳动（VStack 全量布局） |
| 4 | 长按会话 → 重命名 | 弹出半屏 sheet，**键盘自动弹出** |

### 发送

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 输入文字点发送 | 气泡立刻出现，草稿清空 |
| 2 | 发送中再点发送按钮 | **按钮置灰，点不了** |
| 3 | 连发 5 条（`DSH_SEND_BURST=5`） | 全部送达，顺序正确 |
| 4 | 断网点发送 | 进入「待发」状态，联网后自动发出 |

### 图片

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 发送一条带图消息 | 气泡左下角显示缩略图 |
| 2 | 点缩略图 | 全屏打开，清晰（不是缩略图放大） |
| 3 | 全屏左右滑 | 在当前会话的所有图之间翻页，顶部显示 `n / N` |
| 4 | 关闭全屏 5 秒后再打开 | 首次有加载，之后秒开（缓存） |

### 诊断

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 菜单 → 复制诊断 | 报告含 `[ Live Signal ]` 段 |
| 2 | 生成中复制诊断 | `Frames` 有数字，`Rate`/`Gap` 有值 |
| 3 | 空闲时复制诊断 | `Since frame` 递增，说明没在推帧 |

## 怎么加新用例

**判据**：下次改到同一块代码时你会想再跑它。

**格式**：
- 性能用例 → 场景定义 + 基线数字 + 什么改动必须跑
- 交互用例 → 环境变量开关 + 验证点 + 已验证结果
- 功能用例 → 步骤 + 预期（要具体到「按钮置灰」这种可观察的状态，不要写「正常」）

**反例**：「验证发送功能正常」——这不是用例，没法执行也没法判断通过。
