# 全应用布局调试编号体系

> **Status**: Draft
> **起始日期**：2026-11-14
> **预估工时**：240 分钟（单元累加）
> **文件名**：`spec/2026-11-14-1815-layout-debug-full.md`
> **取代**：`spec/2026-11-14-1810-layout-debug.md`（那版只有 L1/L2，编号体系不够）

## 背景 / 问题

调布局时只能靠「上面那行」「过程行和 DSH 那行之间」描述，而相邻的两处间距
（`groupSpacing = 7` / `MessageRow` 内部 `8`）很容易混。

**上一版只接了 L1/L2**，不够用——实际要调的地方遍布列表页和对话页，
需要一个**覆盖全应用、按页分组、编号稳定**的体系。

## 目标与非目标

**目标**
1. 列表页、对话页的**每个可感知元素**都有编号与红框。
2. 编号**按页分组**，一眼能看出是哪个页面的：
   - `S*` = 列表页（Sessions）
   - `C*` = 对话页（Conversation）
   - `G*` = 全局（导航栏等）
3. 关键元素之间的**间距数字**也标出来（显示的是代码里的真实常量值）。
4. 设置页列出完整编号表（编号 → 组件 → 间距值）。
5. 默认关闭，开启后不影响交互。

**非目标**
- 不做运行时实测间距（那是另一套 `GeometryReader` 方案，成本高、收益低）。
  间距数字直接显示**代码里的常量**，标注位置固定在组件附近。
- 不覆盖设置页、连接页（暂时用不到）。

## 方案

沿用上一版的 `LayoutDebug`（`@AppStorage` 开关 + `ViewModifier`），只做三点扩展：

1. **编号表扩到 24 条**（上表），设置页分组展示（列表页 / 对话页 / 全局）。
2. **间距标注**：新增 `layoutDebug(_ id: String, gap: CGFloat? = nil)`。
   传了 `gap` 就在红框**右下角**显示 `7pt` 这样的小字——值是代码常量，不是实测。
3. **逐个打点**：
   - `ConnectedView`（列表页）：S1–S10
   - `ConversationView` / `MessageRow` / `ProcessRow` / `TurnFailureRow`：C1–C12
   - 导航栏与提示条：G1–G2

### 视觉规范

- 描边：`Color.red.opacity(0.75)`，`lineWidth: 0.5`
- 编号：8pt 等宽，红字，白底 85% 衬底，**左上角**
- 间距：7pt 等宽，红字，白底 85% 衬底，**右下角**
- 全部 `allowsHitTesting(false)`

## 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 运行时用 GeometryReader 实测每对相邻元素的间距 | 要给每对元素加 PreferenceKey 与锚点，代码量翻倍，且多数间距是常量、实测等于常量 |
| 自动按渲染顺序生成编号 | 用户要记住编号，编号必须稳定且语义可猜（S=列表、C=对话） |
| 一个全局递增编号（1..24） | 上下文的跳跃感强，`C8` 比 `18` 更容易记住属于哪个页面 |

## 代价与风险

**代价**：24 处打点，约 200 行改动。
**风险**：
| 风险 | 缓解 |
| --- | --- |
| 打点漏了某个分支（比如带图用户气泡） | 打点包在最外层容器，而不是某个分支内部 |
| 编号与设置页表不一致 | 编号表只有 `LayoutDebug.entries` 一个真源，设置页直接遍历它 |
| 描边遮挡细小元素（14pt 图标） | 0.5pt + 半透明；图标本身不动 |
