# 用 AI 写代码：一套可执行的工程方法

> 这套方法来自一个真实的单人 + AI 项目（iOS 客户端，8 天 541 个 commit）。
> 里面每一条都是**踩过坑之后写下来的**，不是理论推演。
>
> 你可以直接拿走用，也可以只挑其中几节。

## 这套方法解决什么

AI 写代码的问题**不是不会写**，是：

| 问题 | 表现 |
| --- | --- |
| **漂移** | 一个需求在几千字上下文里被逐步放大、曲解、夹带私货 |
| **假装完成** | 说「已完成」，实际没跑过一次 |
| **编造事实** | 没查过就说「这个 API 大概不支持」 |
| **空转** | 连续输出「执行」，但没有真实动作 |
| **自我欺骗** | 把「没查到」当成「不存在」，把「没验证」当成「没问题」 |

**这五条都不是知识不足，是行为失范。** 所以需要的是**约束**，不是更多的能力。

## 最小的起步

**如果你只想做一件事**，做这个：

> **每次让 AI 改代码前，先让它写一段「要做什么 / 不做什么 / 做完怎么验收」。**

不需要模板，不需要工具，就是一段话。效果立刻可见：

| 没有这段 | 有这段 |
| --- | --- |
| AI 顺手改了三个不相关的地方 | 它知道「非目标」里写了不许动 |
| 「做完了」但没验收 | 「验收标准」逼它先想清怎么证明 |
| 你以为它做了 A，其实做了 A+B+C | 白纸黑字，能对照 |

## 一句话原则

> **AI 可以说「不知道」「没验证」「卡住了」，
> 但不可以说「完成了」而没有证据。**

这不是不信任 AI，是**让它的可信度可以被验证**。
