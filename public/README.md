# public/ —— 可以公开的材料

这个目录放**对别人有用、且不涉及我们内部实现**的内容。

和它相对的是：

| 目录 | 是否公开 | 放什么 |
| --- | --- | --- |
| **`public/`** | ✅ 公开 | 方法论、协议规范、给插件作者的说明 |
| `docs/` | ❌ 本地 | 截图、ADR、架构快照、参考项目、检查点记录 |
| `spec/` | ❌ 本地 | 带项目细节的实现 spec |

## 这些内容是从哪来的

不是先想好方法论再照着做，而是**反过来**：

1. 先踩坑（AI 说完成了但没验证、引用行号写错、拆了一堆碎片文件反而更难改）
2. 踩完记下来一条规则
3. 规则攒多了，整理成文档
4. 能自动检查的，写成脚本

**所以里面的每一条都对应一次真实的返工。**

## 使用建议

**不用全盘照搬。** 挑你缺的那部分：

| 你的情况 | 建议从哪开始 |
| --- | --- |
| 刚开始用 AI 写代码 | `ai-coding/README.md` 的「最小的起步」 |
| AI 老说「完成了」但没做 | `02-AI-协作约束` 的第 ① 条 |
| 项目大了，AI 总理解错术语 | `03-项目文档体系` 的术语表 |
| 开始有人（或 AI）改你的代码 | `04-质量门禁` |
